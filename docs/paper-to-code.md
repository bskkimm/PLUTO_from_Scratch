# Paper to code and deviations

Sources: [paper v1](https://arxiv.org/html/2404.14327v1) and [official code at b9964b6](https://github.com/jchengai/pluto/tree/b9964b649c660f1f4a971d614c66f5992e24c18a). This is an incomplete educational implementation, not a checkpoint-compatible port.

| Paper | Local implementation | Evidence and limitations |
| --- | --- | --- |
| III-B scene representation | `data.agent_history_features`, `PointEncoder`, `FourierPosition`, `Pluto.encode_scene` | History differences, masks, position Fourier features, and agent/map/static tokens. A three-level local-attention history pyramid replaces the released NATTEN operator and has not been checked for operator parity; state attention, map boundary and categorical attribute inputs are implemented with a different parameterization; released Fourier layout and operator parity remain different. |
| Official preprocessed features | `official_adapter.convert_normalized_batch`, `dataset.BatchManifest` | Converts a normalized, batched official-style tensor dictionary, with analytical fixture only. It does not build full features from raw nuPlan data and is not tested on official cached examples. `nuplan_ego` and `nuplan_actors` read bounded ego/actor windows from SQLite; actor selection uses only nonfuture observations. `nuplan_map` reads nearby GeoPackage lanes, stitches nearby route-filtered lane/connector segments heuristically and reads available traffic-light states. It does not reproduce the official reference-path or map builder; its real-window probe is diagnostic only. `prepare.prepare_nuplan` writes one prepared batch and manifest, including log/map hashes, timestamp, split and mode count. Manifest hashes/split prevent silent resume changes and mode mismatches are rejected. |
| III-C Eq. 4–6 | `Pluto`, `DecoderLayer` | Reference and learned longitudinal embeddings form a Cartesian query grid; attention across each axis then scene cross-attention. Official head layout, mode positional embedding and precise pooling differ. |
| III-C Eq. 7–11 | `free_head`, `imitation_loss`, `prediction_head` | Six channels `[x,y,cos,sin,vx,vy]`; losses sum channels per valid timestep. The adapter implements the released projected-distance/mode-interval rule; `assign_modes` is a separate paper-inspired polyline projection. Official parity is unverified. Paper describes a free head, but released configuration makes it optional and uses four channels when enabled; local head has six. |
| III-D Eq. 12 | `sdf_loss`, `contrastive_objective` | Circle-center lookup and hinge cost, averaged per valid timestep. Pseudocode/released collision code normalize active circles and use different boundary masks. `costmap.signed_distance_field` can build cell-center distance fields from externally rasterized masks; `nuplan_map.rasterize_map_scene` builds a heuristic raster from local drivable polygons and current object boxes; one mini window was tested, but official rasterization parity and broader real-scene validation are missing. Local center and out-of-bounds policy differ from the released code. |
| III-E Eq. 13–14 | `contrastive_objective`, `augmentation` | Original and positive views are supervised; negative encodes only for normalized triplet loss. Optional SDF is applied to the labeled plans. Prepared batches may supply externally validated interaction/leading masks and traffic replacements; synthetic views and real preprocessing remain unvalidated. A caller-specified leading-agent insertion is supported, but donor-frame transformation, placement and causal validity are not automatically established. |
| III-F | `planner.select_trajectory` | Top-K score combination and reference-free fallback, with caller-supplied evaluator. `simulation.lqr_rollout` provides a separate educational bicycle/LQR tracker with analytical fixtures; it is not verified against the official PDM tracker. `rules.score_rollouts` supplies illustrative point-obstacle and SDF gates with displacement scoring; it is not the official nuPlan rule evaluator, collision geometry, or closed-loop evaluation. |
| IV-B | `recipes`, `train` | `paper_shape` matches major dimensions and 3-epoch warmup/cosine schedule; model/data/optimization remain different from the released recipe. Smoke uses a small synthetic fixture. Full training was not performed. |

Masks use `True` for valid. Padded values must be finite; an ego token is always valid. Positions use ego-frame metres, headings use a cosine/sine pair, and velocities use metres per second. Pose keys `[x,y,heading]` are optional for compatibility and default to zero where absent. Real preprocessing, map creation, official scores and checkpoint compatibility remain unverified.

`scripts/compare_nuplan_baselines.py` compares local GeoPackage decoding and projection to the separately installed nuPlan devkit for baselines near a selected ego pose. The [one-window report](../reports/nuplan-baseline-comparison.json) found zero measured geometry distance for 31 paths. The devkit checkout was dirty and the result does not establish feature, route, or planning parity. Run the script with `--help` for its local map and log arguments; it does not download maps.
